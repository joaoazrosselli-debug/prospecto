# Segurança e privacidade

Não publique dados de clientes, telefones particulares, tokens, chaves, senhas, backups ou detalhes de uma conta real em issues ou pull requests.

Para relatar uma falha, envie primeiro uma descrição mínima sem dados pessoais ou um exemplo que comprometa um sistema ativo. A publicação de uma correção exige conferir seu efeito nos controles de acesso e nos dados.

A autenticação de desenvolvimento funciona apenas no ambiente local. A aplicação de produção confia na identidade fornecida pela hospedagem do Sites; mover o servidor para uma hospedagem genérica sem adaptar essa fronteira de confiança é inseguro.

A publicação deste código não concede acesso à base privada nem autoriza consultas ou testes contra a operação em uso.
